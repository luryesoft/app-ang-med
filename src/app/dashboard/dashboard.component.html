In a well-structured application, SQL queries, including SELECT statements, should not be placed directly in the routes.
Instead, they should be encapsulated within the models or services. This approach promotes separation of concerns,
making your code more modular, maintainable, and testable.
Here's a breakdown of where different parts of your code should reside:
1.Routes: Handle HTTP requests and responses. They should call the appropriate service methods
to perform business logic and database operations.
2.Controllers: (optional but recommended for larger applications): Act as intermediaries between
the routes and services. They handle request validation, call service methods, and format the response.
3.Services: Contain business logic and interact with the models to perform database operations.
4.Models: Define the database schema and contain methods for interacting with the database (e.g., SQL queries).
